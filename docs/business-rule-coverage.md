# Business rule coverage

> Generated by `tools/rule_coverage.py` from `docs/homa-business-rule.md` and the `@Tag`s on the tests. Do not edit by hand; run `python3 -I tools/rule_coverage.py` after a merge that changes tests.

Every rule on the rules page has an ID and a case. Each test that specifies a rule carries `@Tag("<rule ID>")` and a `@DisplayName` quoting the rule's case, so `grep -rn '@Tag("RES-11")' src/test` lists the tests behind a rule. This page counts those tags.

## How to read it

| Status | Meaning |
| --- | --- |
| **Domain + usecase** | A test in the owning context's domain and one in a usecase cite the rule. |
| **Domain only** | The business object enforces it; no use case drives it yet. |
| **Usecase only** | A use case cites it, and no domain test does. |
| **Elsewhere only** | Cited only by kernel, values, app or infra tests, such as a number held in a values class. |
| **Not started** | No test cites it. |

A rule marked **partial** is cited, but only part of it is built; the note says which part. "Cited" means a test names the rule. It does not prove the rule is complete.
